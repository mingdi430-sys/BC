# 트렌드 분석 (엔진 C) 발표 정리

## 1. 트렌드 분석이 답하려는 질문

- 예비창업자가 "이 아이템, 지금 들어가도 되나"를 물었을 때 신호등으로 답하는 것이 목표
- 단순히 지금 뜨는지가 아니라 창업 준비 기간(3~6개월)을 감안해 **6개월 뒤에도 수요가 남아 있는지**를 예측
- 아이템은 우리가 손으로 고르지 않음, 데이터에서 자동으로 뽑고 검색 곡선으로 판정하는 구조
- 이유는 생존자 편향 방지, 사람이 "탕후루 떴었지"라고 고르면 성공한 유행만 남고 실패한 유행은 데이터에서 사라짐

## 2. 데이터 수집

### 2-1 아이템 이름 찾기: YouTube Data API
- 업종 11개별 일반 쿼리 50개(예: 편의점 신상, 요즘 뜨는 디저트, 횟집 추천)로 주 단위 영상 검색
- 제목에서 명사구 추출(kiwi 형태소 분석기) → 업종·주별 빈도 집계
- 직전 8주 대비 z-score 3 이상 또는 3배 급등한 명사구를 후보로 선정, 업종당 상위 20개
- 잡음 처리: 제목만 사용, 채널당 1회, 한글 없는 조각·지명·일반명사·해외 여행 영상 제외, HTML 엔티티 정리
- 쿼리는 실측으로 교체함, 12주 수집 후 주당 10건도 안 나오던 9개와 카지노·여행 채널을 끌어오던 1개를 갈아치움
- 하루 키당 100회 제한이라 팀원 키 3개 로테이션, cron으로 매일 16:30 자동 실행
- 현재 40주(2025-12 ~ 2026-09), 영상 7만여 건, 후보 98개(일반어·브랜드·기본메뉴 제외 후), 검증용 라벨인 두쫀쿠·버터떡이 자동으로 잡힘
- 급등(한 주 3배)과 별도로 **완만 상승 탐지**(최근 4주 평균이 직전 8주의 2배 이상, 계속 오르는 모양) → "지금 YouTube에서 뜨는 것" 패널(민음사빵, 피자설기, 한정선 등)
- 불용어는 두 층: 재료어(초코·말차·크림)는 단독일 때만 제외해 초코바게트·말차쇼콜라 같은 복합어를 살리고, 쿼리·장르·일반어는 복합어에 섞여도 제외

### 2-2 검색 곡선 받기: 네이버 검색어 트렌드 (NAVER API HUB)
- 2020년부터 주간 곡선, 세그먼트 9개(전체 / 남녀 / 연령 6구간)
- 네이버는 요청 안 최대값을 100으로 놓은 상대값만 주기 때문에 요청마다 척도가 다름
- 해결: 모든 요청에 앵커 키워드 "쿠팡"을 같이 넣고 쿠팡 평균으로 나눠 척도 통일, 값이 너무 작은 키워드는 쿠팡 → 업종 앵커 → 키워드 2단으로 연결
- 지역 시차용으로 "서울 탕후루" 같은 5대 도시 조합도 수집
- 현재 271개 키워드(라벨 14 + 후보 + 지역 조합 + 데모), 약 69만 행, 원본 응답은 전부 캐시라 재호출 없음
- 풀에 없는 아이템을 검색하면 그 자리에서 네이버 곡선을 받아 판정(온디맨드, 20~30초, 이후 캐시)

### 2-3 검증용 라벨
- 유행 7개(크로플, 탕후루, 두바이 초콜릿, 두쫀쿠, 마라탕, 오마카세, 소금빵)와 안정 7개(김밥, 떡볶이, 치킨, 삼겹살, 짜장면, 라면, 우유)
- 반감기 기대값은 코리아헤럴드 2026-02-08 기사(원자료 네이버 데이터랩)
- 이 라벨은 채점에만 쓰고 후보 생성에는 절대 넣지 않음

## 3. 분석 방법 세 층

### 3-1 규칙 단계 판정 (지금 어디인가)
- 매주 그 주까지의 데이터만으로 최근 4주 성장률, 가속(성장률 변화), 역대 최고 대비 수준, 신호 유의성(t-통계량)을 계산
- 태동 / 급등 / 정점 / 하락 / 안정 다섯 단계, 미래 데이터는 절대 안 씀(롤링)
- 안정 품목 7개를 급등으로 오판한 횟수 0

### 3-2 반감기 (얼마나 빨리 식나)
- 정점에서 절반으로 떨어질 때까지 일수
- 정의 4종 비교: 주간 원본 / 스플라인 평활 / 일간 원본 / 일간 7일 이동평균
- 일간 7일 이동평균이 기사 수치와 평균 오차 2.5일로 일치(크로플 163 vs 163, 탕후루 59 vs 54, 두바이 초콜릿 12 vs 13, 두쫀쿠 21 vs 17)
- 주간 원본은 오차 13.5일, 평활은 정점을 깎아 과대추정, 정의를 데이터로 고른 과정 자체가 발표 포인트

## 4. 모델 비교: 어떻게 성능을 쟀나

### 잣대
- 질문: 주 t까지의 곡선만 보고 26주 뒤 검색량이 지금(최근 4주 평균)의 70% 이상 남는가
- 4주 간격 rolling origin, 미래 정보 없음, 곡선 183개(라벨 14 + 데모 + 후보)에서 시점 12,826개
- 지표는 AUC(1이 완벽, 0.5가 무작위)
- 학습 모델은 키워드를 10개 그룹으로 나눠 그룹 단위로 학습·평가(같은 곡선의 시점을 양쪽에 두면 성적이 부풀기 때문)

### 입력과 출력
- 특징 기반 모델 입력: 성장률, 가속, 최고 대비, 유의성, 12주 변동성, 정점 후 경과 주, 수준 → 출력: 유지 확률
- LSTM 입력: 최근 52주 곡선 원본 → 출력: 유지 확률
- TimesFM 입력: 곡선 전체(숫자 배열 하나) → 출력: 26주 점 예측 + 분위수 → 유지 확률로 변환

### 결과 (2026-09-20, 곡선 183개)

| 모델 | 전체 AUC | 라벨 15개만 | 유행 키워드만 |
|---|---|---|---|
| 규칙 한 줄(최근/직전 비율) | 0.295 | 0.509 | 0.524 |
| 로지스틱 회귀 | 0.732 | 0.672 | 0.648 |
| 랜덤포레스트 | 0.823 | 0.710 | 0.688 |
| XGBoost | 0.826 | 0.722 | 0.688 |
| LightGBM | 0.822 | 0.710 | 0.682 |
| 그래디언트 부스팅(sklearn) | 0.825 | 0.718 | 0.680 |
| LSTM (최근 52주 원본) | 0.880 | 0.799 | 0.705 |
| **TimesFM (zero-shot)** | **0.912** | **0.855** | **0.756** |
| TimesFM + 특징 스태킹 | 0.893 | 0.826 | 0.743 |

- 곡선이 15개에서 183개로 늘자 학습 모델이 전부 올라옴, 특히 LSTM은 0.55 → 0.88(데이터 양이 문제였다는 증거)
- 트리 계열 넷(RF·XGB·LGBM·GBM)은 0.82~0.83으로 사실상 같음, 특징 7개의 한계
- 그래도 TimesFM이 1등, 사전학습 덕에 데이터 없이도 앞서고 데이터가 늘어도 앞섬
- 규칙 한 줄이 0.3(무작위 이하)인 것은 "최근에 오른 것일수록 6개월 뒤 떨어진다"는 유행의 본성, 로지스틱 계수도 성장률 −4.16, 가속 +2.03으로 같은 말
- 유행 키워드만 보면 모두 0.65~0.76으로 낮음, 완만한 유행(크로플·소금빵)은 여전히 어려움

### TimesFM 세부 검증 (곡선 183개, 12,826 시점)
- 초록(유지 확률 80% 이상) 판정 78% 중 실제 유지 96%
- 빨강(50% 미만) 판정 11% 중 실제 하락 73% (라벨 15개만 볼 때는 48%였음, 표본이 커지며 안정)
- 실제 하락 중 빨강으로 잡은 비율 57%
- 틀리는 곳은 급등 직전(탕후루 정점 12주 전 16%라고 비관, 실제 37% 상승)
- 그래서 빨강인데 규칙 단계가 태동·급등이면 노랑으로 낮추는 보정을 넣음
- 완만한 유행(크로플 0.53, 소금빵 0.57)에는 약함, 표본의 90%가 유지라 안정 품목이 성적을 올리는 점도 한계로 명시

## 5. 최종 모델 TimesFM: 원리

- Google Research의 시계열 파운데이션 모델, 한 줄로 "시계열용 GPT"
- 값 32개를 토큰 하나(패치)로 묶어 디코더 전용 트랜스포머에 넣고 한 번에 128개 값을 출력
- 각 위치는 자기보다 앞선 패치만 봄(causal), 문맥 첫 패치 기준으로 표준화하므로 척도와 무관
- 약 1,000억 시점의 시계열(Google Trends 검색량, 위키 페이지뷰, 공개 시계열, 합성 데이터)로 "다음 구간 맞히기" 사전학습
- 출력은 점 예측과 함께 분위수 0.1~0.9, 우리는 2.5 버전(2억 파라미터, 문맥 16k, 연속 분위수 헤드)을 CPU로 사용, 곡선 하나 0.2초
- 검색 트렌드가 사전학습에 포함돼 있는 것이 zero-shot으로 성적이 나온 이유 중 하나

## 6. 분석 흐름: 실제 입출력 예(탕후루)

- 입력: 주간 검색 지수 350개짜리 숫자 배열 하나, 날짜·이름·업종 없음
- 출력: 26주 점 예측 26개 + 분위수 표(26주 × 9분위)
- 26주 뒤 행 예: q10 0.000 / q50 0.083 / q90 0.205 → 멀수록 폭이 벌어짐, UI의 부채꼴 음영이 이것
- 유지 확률: 지금 수준 0.117의 70%인 0.082가 23~26주 분위수 어디에 걸리는지 읽음 → q40과 q50 사이 → P(유지) 0.52 → 노랑
- 중앙값 0.085 / 지금 0.117 = 0.72 → "6개월 뒤 검색량은 지금의 약 72%"
- 백테스트는 이 계산을 과거 시점에서 1,033번 반복해 실제와 비교한 것

```
검색 곡선(주간, 앵커 정규화) ─▶ TimesFM ─▶ 26주 분위수 ─▶ P(26주 뒤 ≥ 지금의 70%) ─▶ 신호등 색
                                  규칙 단계 ─────────────────────────┘ 빨강인데 상승 구간이면 노랑
```

## 7. UI에서 보이는 것

- 트렌드 분석 탭, 아이템 검색(자동완성) 또는 업종별 아이템 칩, 검색 전 화면에는 "지금 YouTube에서 뜨는 것" 카드(12주 스파크라인, 클릭하면 판정)
- 풀에 없는 아이템은 즉석 수집 후 판정(예: 약과 26초, 마라샹궈 12초)
- 맨 위 판정 한 문장 + 카드 3개: **현재**(기본 수요 / 정착한 유행 / 꺼진 유행 / 유행 초입 / 급등 중 / 하락 중) → **3개월 뒤** 유지 확률 → **6개월 뒤** 유지 확률, 색은 6개월 기준(80% 이상 초록, 50% 미만 빨강)
- 문구는 판정이 아니라 신호로: "6개월 뒤에도 수요가 남을 가능성이 높습니다 · 유행 리스크 낮음" (들어가도 된다는 말은 쓰지 않음)
- 곡선 하나: 기본 최근 2년 + 26주 예측 부채꼴, 아래 얇은 띠로 주별 단계, "2020년부터 전체 보기" 토글
- **타임머신 슬라이더**: "이 시점에 봤다면" → 그 주까지의 데이터만으로 낸 판정과 부채꼴, 그 뒤 실제 곡선은 회색으로 겹침 (탕후루 2023-05 노랑 → 2023-09 빨강)
- 누가 찾는가: 검색 세대 최다 vs 상권 탭 결제 세대 최다가 같은지 한 문장, 연령 비중 막대는 펼침
- 어디서 먼저 뜨는가: 서울 대비 정점 몇 주 차이, 선택 지역 강조
- 근거·한계(반감기, 정점, 모델, 백테스트 수치, 기준일)는 "어떻게 계산했나요" 접이식

## 8. 한계와 다음 단계

- 2026년 9월 현재 초입·급등 단계 아이템이 거의 없음(비수기), 타임머신이 그 공백을 메우는 장치
- 스태킹(0.893)이 TimesFM 단독(0.912)을 아직 못 넘음, 곡선이 더 쌓이면 재시도
- 후보 생성이 YouTube 제목 하나에 의존해 초코바게트처럼 작은 신호는 놓침(온디맨드 검색으로 보완)
- 폐점률 검증: 지방행정인허가 데이터로 상호에 아이템명이 든 매장의 개업·폐업 곡선을 뽑아 검색 정점 → 개업 정점 → 폐업 정점 시차 확인, 정답을 "검색량 유지"에서 "12개월 생존"으로 바꾸는 것이 목표
- 빅카인즈(뉴스)를 두 번째 후보 원천으로 붙이면 유튜브 편향 보완
