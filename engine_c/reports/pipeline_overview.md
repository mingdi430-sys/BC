# 엔진 C 데이터 파이프라인 정리

아이템 이름을 찾는 길과, 그 아이템의 검색 곡선을 받는 길이 다르다. 이 둘을 분리한 이유는 우리가 아이템을 손으로 고르지 않기 위해서다. 사람이 "탕후루가 떴었지"라고 고르면 성공한 유행만 남는 생존자 편향이 생긴다. 그래서 이름은 모집단 데이터에서 자동으로 뽑고, 네이버 검색 트렌드는 곡선 조회에만 쓴다.

## 1단계. 아이템 이름 찾기 (YouTube, 매일 자동)

업종별 일반 쿼리 50개로 YouTube Data API를 주 단위로 검색해 영상 제목을 받는다. 제목에서 명사구를 뽑아 주간 빈도를 세고, 직전 8주 대비 갑자기 늘어난 명사구(z-score 3 이상 또는 전주 대비 3배)를 후보로 잡는다. 업종당 상위 20개까지.

여기서 나오는 것은 **이름 목록**뿐이다. 예: 찹쌀떡, 크림새우, 갈비탕. 검색량 곡선은 이 단계에서 만들지 않는다.

쿼리는 아이템 이름이 아니라 업종 수준의 일반어만 쓴다. 검증용 라벨(크로플, 탕후루 등)은 절대 쿼리에 넣지 않는다.

| 업종 | 쿼리 |
|---|---|
| 대형할인점 | 코스트코 신상, 이마트 추천템, 트레이더스 신상, 대형마트 꿀템, 홈플러스 신상 |
| 편의점 | 편의점 신상, 편의점 디저트, 편의점 꿀조합, 편의점 신제품 리뷰, 편의점 추천 |
| 슈퍼마켓 | 마트 신상, 마트 추천 간식, 마트 꿀템, 마트 장보기 추천 |
| 일반한식 | 한식 신메뉴, 요즘 뜨는 한식, 한식 맛집 유행, 한식 먹방 신상 |
| 갈비전문점 | 고기집 추천, 고기집 신메뉴, 갈비 먹방, 요즘 뜨는 고기집 |
| 한정식 | 한정식 맛집, 한식 코스요리, 한상차림 맛집, 한식 파인다이닝 |
| 일식회집 | 일식당 추천, 일식 먹방, 횟집 추천, 초밥집 추천, 초밥 유행 |
| 중국음식 | 중식 신메뉴, 중식당 추천, 중국집 신메뉴, 중화요리 먹방 |
| 서양음식 | 양식 신메뉴, 요즘 뜨는 양식, 브런치 유행, 파스타 맛집 신상, 양식 먹방 |
| 스넥 | 분식 신메뉴, 요즘 뜨는 간식, 길거리 음식 유행, 간식 먹방 신상, 분식 먹방 |
| 제과점 | 빵집 신상, 요즘 뜨는 디저트, 베이커리 유행, 디저트 신상 먹방, 카페 디저트 유행 |

쿼리는 고정이 아니라 실측으로 고친다. 12주 수집 뒤 주당 10건도 안 나오던 9개와 여행·카지노 채널을 끌어오던 1개, 총 10개를 교체했다(예: 회집 유행 → 횟집 추천, 일식 맛집 신상 → 초밥집 추천).

수집은 하루 키당 100회 한도라 팀원 키 3개를 돌려 하루 300회씩 cron으로 자동 실행한다. 지금 40주 범위 중 900개 작업이 끝났고 20일에 마감된다. 노이즈 처리로 제목만 사용, 채널당 1회, 한글 없는 조각·지명·일반명사·해외 여행 영상은 제외한다.

현재 후보 162개. 제과점에서는 두쫀쿠가 사람 개입 없이 잡혔다.

## 2단계. 이름을 곡선으로 바꾸기 (네이버 검색 트렌드)

이름 하나를 네이버 검색어 트렌드 API(NAVER API HUB)에 넣으면 2020년부터 지금까지 주간 검색량 곡선이 나온다. 전체, 성별 2, 연령 6, 총 9개 세그먼트로 받는다.

네이버는 요청 안 최대값을 100으로 놓은 상대값만 주기 때문에 모든 요청에 앵커 키워드 "쿠팡"을 같이 넣고, 쿠팡 평균으로 나눠 척도를 통일한다. 값이 너무 작은 키워드는 쿠팡 → 업종 앵커 → 키워드 2단으로 잇는다.

후보 162개의 곡선은 아직 받지 않았다. 후보 목록이 매일 바뀌는 중이라 20일에 확정한 뒤 한 번에 받는다(약 200개, 하루치 호출).

지금 곡선이 있는 것은 **검증용**뿐이다. 크로플·탕후루·두바이 초콜릿·두쫀쿠·마라탕·오마카세·소금빵(유행 7개)과 김밥·떡볶이·치킨·삼겹살·짜장면·라면·우유(안정 7개)는 YouTube가 찾은 게 아니라 답을 아는 과거 사례로 우리가 적어 둔 라벨이고, 판정 장치가 맞는지 채점하는 데만 쓴다. 여기에 지역 시차용 "서울 탕후루" 같은 조합 70개와 데모용 비빔밥 6개를 더해 곡선 90개다.

## 3단계. 곡선을 판정하기 (규칙 + TimesFM)

곡선이 있어야만 돌아간다.

- 규칙: 각 주까지의 데이터만으로 최근 4주 성장률과 가속을 계산해 태동·급등·정점·하락·안정 중 하나를 붙인다. "지금 어느 단계인가"를 설명하는 층이다.
- TimesFM: 사전학습 시계열 모델(2.5, 200M, 추가 학습 없음)에 곡선을 넣어 26주 예측을 받고, "6개월 뒤 검색량이 지금의 70% 이상 남을 확률"을 낸다. 신호등 색은 이 확률로 정한다(90% 이상 초록, 50% 미만 빨강).
- 반감기: 정점에서 절반으로 떨어질 때까지의 일수. 일간 곡선에 7일 이동평균을 쓰면 코리아헤럴드 기사 수치와 오차 2.5일로 일치했다.

TimesFM 백테스트는 곡선이 검증용 15개뿐이라 그 위에서만 돌렸다. 4주 간격으로 잘라 1,033개 시점, AUC 0.855(규칙 0.486). 초록 판정은 실제 유지 98%로 정확하고, 빨강은 절반만 맞는데 틀리는 곳이 급등 직전 한 종류라 규칙 단계와 교차해 읽으면 된다.

## 그림

```
YouTube 50개 쿼리 ──▶ 급등 명사구(후보 162개)  ── 현재 여기까지
                                     │
                                     ▼ (20일, collect)
                          네이버 검색 곡선 받기 ──▶ 규칙 단계 + TimesFM 6개월 예측 ──▶ 신호등
                                     ▲
labels.yaml(검증용 14개) ─────────────┘  ← 12일에 받음, 채점에만 사용
```

## 데이터 모이면

후보 확정 → 후보 곡선 약 200개 수집 → 규칙·TimesFM 적용 → 업종별 아이템 신호가 처음 생긴다. 백테스트 표본도 곡선 15개에서 200개로 늘어 검증 수치가 지금보다 믿을 만해진다. 지금 UI의 비빔밥·라벨 곡선은 그 결과물의 모양을 미리 보여주는 것이다.
